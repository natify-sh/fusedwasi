# S0007: The error of a path that leaves the preopen in WASI 0.1 (row E1)

**Status:** accepted 2026-11-05 (the owner accepted option A as proposed in section 4; no code changes). Written the same day so that an open question of `docs/release_checklist.md` (section 6) is not lost. The facts are marked as in the other documents of `docs/`.

## 1. The problem

For any path that leaves the preopen (`..`, `/etc/passwd`, `sub/../..`, a link out), 0.1 answers `NOTCAPABLE` and Wasmtime `PERM` **[read: `docs/wasmtime_compare.md`, row E1; 30 steps in the experiment]**. The row is marked **deliberate**, from the comment in `wasi_p1_files.py`: a way out of the directory is `NOTCAPABLE` when it comes from a walk and `EPERM` when it comes from the system **[read]**. The specification of 0.1 does not say which error such a path gets, so the row stays **open** as a word.

## 2. Options

* **A. Keep `NOTCAPABLE`.** It is the error that the capability model names; the official wasi-testsuite is run by the CI (job `python-wasmtime`, 72 tests of the commit `9dfd486`) and holds it **[read: release_checklist, step 2]**.
* **B. Follow Wasmtime (`PERM`).** A guest that was written against Wasmtime sees the same code. A guest that checks for `NOTCAPABLE` sees a change.
* **C. Keep both as a setting.** More surface for a word.

## 3. What decides it

Which guests exist: wasi-libc maps both codes to an `errno`, `ENOTCAPABLE` and `EPERM` **[not checked: from memory of wasi-libc]**; a program that tells the two apart is rare. The cost of a change is the tests in both twins (`tests/data/p1/*.txt`) and the compare document.

## 3.1 Where the other hosts get their code (read 2026-11-05)

* **Wasmtime** gets `PERM` as a side effect of its layers, not from a choice about escapes **[read: `bytecodealliance/wasmtime`, `crates/wasi`]**. The sandbox is `cap-primitives` (now a copy inside `crates/wasi/src/filesystem/primitives/`): `openat2` with `RESOLVE_BENEATH` on Linux, `O_RESOLVE_BENEATH` on FreeBSD, a manual walk elsewhere. Its `escape_attempt()` returns an `io::Error` of kind `PermissionDenied` with no `raw_os_error` (`primitives/errors.rs`). `From<&io::Error> for ErrorCode` (`filesystem.rs`) maps that kind to `ErrorCode::NotPermitted`, and the 0.1 adapter (`p1.rs`) maps `NotPermitted` to `Errno::Perm`. So 0.1 gets `PERM` because 0.1 is built over 0.2 and the 0.2 code for a generic denial is `not-permitted`.
* **uvwasi** answers `UVWASI_ENOTCAPABLE` for a normalized path that is not under the descriptor's path and for an absolute path (`src/path_resolver.c`, three places) **[read: `nodejs/uvwasi`, shallow clone of 2026-11-05]**. The one `EPERM` is an absolute `old_path` of `path_symlink` (`src/uvwasi.c`), which is not an escape by a walk **[read]**; fusedwasi refuses `path_symlink` with an absolute target as `NOTCAPABLE` (row E11 of `wasmtime_compare.md`) **[read, not run here]**, so that one case differs from uvwasi too.
* **Not checked:** that Wasmtime returns `PERM` for all 30 steps of E1 by this route (the code was read, not run), and the Windows route (`primitives/windows/errors.rs` was only listed).

## 4. Proposal (a draft)

A, closing the word: the row says "deliberate, decided" and `host_scope.md` gives the reason; no code changes. Only if the official testsuite of a newer commit asks for `PERM`, this is reopened.

## 5. Decision

1. Keep `NOTCAPABLE` as final: **yes** (2026-11-05). Row E1 of `wasmtime_compare.md` is closed as deliberate, with the reason of section 3.1. Reopened only if the official testsuite of a newer commit asks for `PERM`, or if Wasmtime gives escapes a code of their own.
