# S0013: `wasi:http`, the transport: the plan (Python first, on `h11`)

**Status:** accepted 2026-11-05 (the owner decided each point of section 1). It **replaces** [S0012](S0012.md) (the parity policy) and [S0014](S0014.md) (the tree of sizes), which are merged here and now only point to this page. Steps are in section 6; what is still open is in section 8. The facts are marked as in the other documents of `docs/`.

## 1. What was decided

1. **The scope is what Wasmtime does, no more and no less.** Against Wasmtime, Spin and the JS shim of `jco` (read 2026-11-05, section 2) the library has **one real gap in `wasi:http`: the body of an answer is read whole before the guest sees it** ([S0003](S0003.md)). Everything else that was discussed (redirects, proxies, HTTP/2) is **not** done by Wasmtime or Spin and is **deferred**, section 7.
2. **Python first, C later.** A new behaviour of the transport of `wasi:http` may land in the Python twin before the C twin. Until then the difference is written down as the TLS one is (a row of `docs/features.json` with a source file on each side, and a limit in `docs/host_scope.md`), and the C test is an `xfail(strict=True)` that names this spec. The parity stays for everything else: the surface a host touches, the 200 imports and their signatures, WASI 0.1, and every behaviour that exists in both twins today (`docs/design_model.md`, section 6).
3. **The Python twin takes `h11` as a required dependency** (`h11>=0.16,<1`, in `pyproject.toml`; `uv.lock` has it and nothing else). `h11` is pure Python and has **no dependencies of its own** (the file `WHEEL` says `py3-none-any`, `Root-Is-Purelib: true`; checked on CPython 3.13, PyPy 8.0.1 and Pyodide 314.0.7). Anyone who installs `fusedwasi` for the C headers gets it too; that was accepted. Any later dependency of the Python twin must be pure Python, with all of its own dependencies.
4. **`h11` does the protocol, we keep the rest:** sockets, DNS, the three timeouts, `ssl`, the policy check and the mapping to `error-code` stay ours. The standard library (`http.client`, `urllib`) is **not** used for the answer: `http.client` discards the trailers and adds headers the guest did not set (`Accept-Encoding: identity`; `urllib` also `User-Agent`, `Connection`, and changes the case) **[run: 2026-11-05]**.

## 2. Why: what the others do **[read, 2026-11-05; "no" means no match in the text]**

| | HTTP/1.1 by | Body of the answer | Redirects | Proxy variables | HTTP/2 | Trailers out |
| --- | --- | --- | --- | --- | --- | --- |
| Wasmtime (`wasi-http`, transport 271 lines) | `hyper` | stream | no | no | no (default sender) | yes |
| Spin (`factor-outbound-http`) | `hyper_util` | stream | no | no | yes (a comment says so) | yes |
| `jco` shim, Node (800 lines) | `node:http` | stream | no | no | no | "unsupported" |
| `jco` shim, browser (1116 lines) | `fetch` | stream | by `fetch` | by the browser | by the browser | "unsupported" |
| WasmEdge | a stub of 186 lines, off by default | | | | | |
| Wasmer | no `wasi:http` (it has WASIX) | | | | | |
| **fusedwasi** | own client | **whole, at most 256 MiB** | no | no | no | yes |

Wasmtime maps errors coarsely (all else is `HTTP-protocol-error`); ours is finer, which is not required.

**Sizes [measured, lines]:** the resource model of `wasi:http` is about 1.1k lines in each twin (C 1126, Python 1135) and is needed whatever is done; the transport is C 754 (connect 130, TLS glue 167, request 43, answer parser 209, orchestration 98) and Python 246 (of which the hand parser and writer are 155: `_Reader`, `_parse_fields`, `_read_head`, `_read_body`, `_read_chunked`, `_build_request`). The libraries: `h11` 1497 code lines, `h2` 4532 + `hpack` 5270 + `hyperframe` 722 (docstrings and tables counted). A self-written HTTP/2 client would be 5 to 10 times the whole transport and could not be tested against itself.

## 3. How the Python transport changes

* **Replaced by `h11`:** the 155 lines of the hand parser and writer. **Kept:** `_connect`, `_dns_error`, `_connect_error`, the wrap of `ssl`, the timeouts, `default_send`'s order of work.
* **Streaming:** the loop is: read a piece from the socket, `receive_data`, take the events. `Response` gives the status and the headers; each `Data` is a piece of the body; `EndOfMessage` gives the end and the trailers. The body of the answer becomes an `InputStream` over this loop (today it is `MemoryInput` over bytes): `read(n)` gives what is buffered, `ready()` is true when there are bytes buffered, or the socket is readable (or `ssl.pending()`), or the answer ended. The host's wait is the one that exists (`ready` polled with the guest's `wait`).
* **The total limit** (`MAX_BODY`, 256 MiB) stays as a limit of the total; an answer that breaks after the head reaches the guest as an error of the stream and through `http-error-code`.
* **A custom `http_send` is unchanged:** it returns a whole answer, which is a body source too.

## 4. The mapping from `h11` to the `error-code` that the tests pin **[run: h11 0.16.0 on each case]**

| Case | What `h11` does | We answer |
| --- | --- | --- |
| Content-Length; chunked with an extension and trailers; HEAD; 204; until-close | the events; trailers come on `EndOfMessage` | as now |
| `100 Continue` before `200` | `InformationalResponse`, then `Response` | as now |
| Cut short (length 100, 10 sent) | `Data`, then an error at the end of the stream | `HTTP-response-incomplete` (we know it is the end of the stream) |
| Garbage for a status; bad chunk size | `RemoteProtocolError` | `HTTP-protocol-error` |
| `101` | `RemoteProtocolError` | `HTTP-upgrade-failed`, recognised by `HTTP/1.1 101` in our buffer before `h11` sees it |
| `Transfer-Encoding: gzip` | `RemoteProtocolError` | `HTTP-response-transfer-coding: gzip`, the value read from our buffer |
| A head larger than `MAX_HEAD` that arrives in pieces | an error of the buffer | `HTTP-response-header-section-size`, with `max_incomplete_event_size = MAX_HEAD` |

A case is decided by **where it happened** (the head, the body, the end of the stream), not by the text of the error.

## 5. The contract of `http_send` (what both twins share)

The request is as today. The answer has status and headers first and **a body that is a source** (`read`, `ready`, `close`; a whole `bytes` / blob is the simple case); the trailers are known after the end. The policy check (`http_check`) is called once, before the transport, as today; a transport that makes another connection (none does now) would have to call it again. The C twin gets the same shape later: its `fusedwasi_p2__http_conn_read` already takes `ms`, its answer parser has to become incremental, and **what `timeout_ms == 0` means in `read` of the TLS hook is not written in `docs/tls_hook.md`** and has to be, before a C source can be non-blocking over TLS.

## 6. The steps (one commit each)

1. **Done 2026-11-05:** the dependency (`pyproject.toml`, `uv.lock`) and these pages.
2. **Done 2026-11-05:** the Python transport on `h11`, **whole body still**, the mapping of section 4 (`_Answer` and `_send_request` in `wasi_p2_http.py`; the hand parser of 155 lines is gone). All the tests of both twins stayed green with no change (`tests/test_wasi_p2_http.py`: 21 tests, the same scenarios compared with the C twin; the whole suite 322 passed on CPython, and the http tests on PyPy 8.0.1). The job `android` stages `h11` into the app (`test.yml`).
3. **Done 2026-11-05:** the answer as a stream in the Python twin (`_BodySource`, `_Answer.poll`, `_default_open` in `wasi_p2_http.py`). A read never waits; a failure comes after the bytes that came before it, as the error of the stream, and `http-error-code` gives its `error-code`; the trailers are known when the body ended; the socket is closed at the end, on a failure, and when the body or its trailers are dropped. Tests (`tests/test_wasi_p2_http.py`): a server that drips (`/drip`), stalls (`/stall`), resets in the middle (`/reset`) and never ends (`/endless`), and the total over a lowered limit. The two cases that break after their head (`truncated`, `bad chunk`) moved from the scenario `main` to `late_errors`, whose comparison with the C twin is an **`xfail(strict=True)`** that names this spec. `docs/host_scope.md` (the limit is now "Bodies of http: the C twin reads the answer and sends the request whole"), `docs/features.json` (`streamingBodies`: C false, Python partial) and the tests of `features` say what is done. The suite: 328 passed, 17 skipped, 1 xfailed on CPython; the http tests on PyPy 8.0.1. Not run on Windows and macOS yet (the CI of this commit will).
3b. **Done 2026-11-05:** the body of a request goes out as it is written **when the answer is asked for before the body is finished** (the guest no longer waits for ever; `_RequestSender`, `_RequestBodyOutput`, `_FutureIncomingResponse._start` / `_go_on`). A body that is finished first is sent whole with its length, as before and as in the C twin, so no existing output changes. Otherwise the head goes out with `transfer-encoding: chunked`, or, if the guest declared `content-length`, as it is; the writes are given to the socket as it takes them and `check-write` is the room that is left (64 KiB ahead, and the total limit); the answer is read without waiting and delivered when its head is here, even before the request is all out; the first-byte timeout starts when the request is all out. Tests: `test_the_answer_may_come_before_the_body_is_finished` (a server that answers after the first bytes of the body, both with chunks and with a declared length; a watchdog fails it if the guest waits for ever; it fails so on the code before this change). The C twin is unchanged and does not have this (no test of it: its driver would wait for ever).
4. The C twin, when it is wanted: an incremental parser and a non-blocking read; the `xfail` is removed.

## 7. Deferred (not needed for parity with Wasmtime and Spin)

* **Redirects and proxies** ([S0004](S0004.md)). If they are ever added: two settings on the state, both off by default (`http_redirects`, a number of hops; `http_proxy`, `None`, `"env"` or `"host:port"`); a redirect to another authority refused by default, because the standard rule of `urllib` lets `Authorization` follow it **[run]**; the policy check on every hop. About 80..250 lines per twin **[estimate]**.
* **HTTP/2** ([S0005](S0005.md)): `h2` (pure, with `hyperframe` and `hpack`, all `py3-none-any`) if it is ever wanted; self-written is out of reach and untestable without a reference server.
* **TLS settings in Python** ([S0006](S0006.md)): small, Python only (the C twin has the hook), not a requirement of Wasmtime.

## 8. Open

1. **The body of a request: done in the Python twin (step 3b).** Wasmtime hands the request body to `hyper` as a stream; ours now goes out as it is written when the answer is asked for before the body is finished. Still open: a request that the guest writes in pieces **without** asking for the answer first is kept and sent whole when the answer is asked for, which differs from Wasmtime only in when the bytes leave, not in what a guest can see **[read: `http_impl.rs`; the concurrency is inferred, not run]**; and the C twin.
2. A guard test that the dependencies of the Python twin are pure Python (install with `--only-binary=:all:`, check the tag of every distribution), opt in because it needs the network.
3. The wording of the README for the Python twin: it needs `h11`, and a feature that only Python has until step 4.
4. The reference to compare a Python-only feature with, since C cannot be: Wasmtime (`docs/specs/S0008.md`).
