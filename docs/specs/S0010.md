# S0010: Android in the CI: what the job is, and what it is not (state of 2026-11-05)

**Status:** draft (a record of the state and a proposal; the owner decided on 2026-11-05 that the job is **not required** for a merge, and the rest is open). The facts are marked as in the other documents of `docs/`.

## 1. What exists

The job `android` of `.github/workflows/test.yml` (name "the Python twin in an Android app (emulator, x86_64)") **[read]**: the python.org Android package 3.14.10 (pinned by SHA-256), the testbed app of CPython, a Gradle-managed emulator with KVM, Android 15, SELinux `untrusted_app`. The tests are the files that `tools/android_check.py` lists: the Python twin, with the tests that build C skipped (an app has no C compiler). It is the recipe of the repository `natify-sh/waboros` **[read: its `ci.yml`, job `android`]**.

Runs **[run]**:

* the first, job 127192486115: 96 passed, 1 failed (`test_values`), 49 skipped. The failure was a finding, not a bug of the job: the SELinux of an app refuses a hard link (`avc: denied { link }` in the log) and the scenario went on with a file that was never made;
* after the test was changed to skip where the system refuses a hard link (reason: "this system refuses a hard link to a program (Permission denied)"): 96 passed, 50 skipped, 0 failed, job 127196044115, commit `e579643`; the head of the pull request `4892410` is green with it. Two green runs are all there is **[run]**.

## 2. The decision of the owner

The job is **not required for a merge**. At the time of writing the branch `main` has no protection and no ruleset, so no check is required at all **[run: `branches/main/protection` answers 404 "Branch not protected", `rulesets` is empty]**; the job is informative: it shows red in a pull request and nobody is blocked by it. If a protection is turned on later, this job is **not** to be added to the required checks without a new decision.

## 3. Why not required (the reasons I gave, for the record)

* it depends on downloads that the repository does not control: the SDK and the system image through Gradle, the package of python.org;
* two runs say nothing of its stability;
* it runs 50 of 146 tests of the files that it lists, and what it finds is most often a property of Android (the hard link) and not a regression;
* it is the longest job of the matrix (about 4 minutes on the first run **[run]**).

## 4. Open

* **What it does not cover:** the C twin (no compiler in an app; building the C drivers with the NDK and running them in the app is a larger piece of work and is **not started**), arm64 (GitHub has no arm64 runner that can run the emulator), other versions of Android (only the newest, `maxVersion`).
* **The code of the hard link:** the system answers `EACCES`; what the host answers for it is **[not checked]**, because the test skips before the call. A test that makes the call and pins the code (in the Python twin, on any system that refuses a hard link) would close it.
* **Stability:** how often the job fails without a cause in the code is not known. A line in `docs/release_checklist.md` (section 6) is where the count can be kept.

## 5. Proposal (a draft)

Keep the job as it is, informative. After some weeks, if it has not failed without a cause in the code, say so here and let the owner decide again whether it is worth a place among the required checks. Do not widen it (the NDK, arm64) before a user of the library on Android is known.

## 6. For the owner to decide (later)

3. Is the test that pins the answer to a refused hard link wanted?
