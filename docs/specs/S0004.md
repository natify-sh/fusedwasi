# S0004: Redirects and proxies for `wasi:http`

**Status:** deferred 2026-11-05: it is not needed for parity with Wasmtime and Spin, which do not have it (S0013, sections 2 and 7). Kept as the record of what it would take.

## 1. The problem

A request is HTTP/1.1 with `Connection: close` and a connection of its own. A 3xx answer is the answer: the guest sees the status and `Location` and no second request is made **[run: `test_http_a_redirect_is_not_followed`, and `_in_c`]**. The variables `HTTP_PROXY`, `ALL_PROXY` and the like are not read **[run: `test_http_proxy_variables_are_not_read`, and `_in_c`]**. Both are in `host_scope.md` (Known limits) as deliberate, for the alpha.

## 2. Redirects

The WIT gives the guest the request and the answer; a guest that wants to follow a redirect can do so, with its own policy (the method on 301/302/303, a header such as `Authorization` that must not follow to another host). A host that follows by itself takes these decisions from the guest and does so with the network policy of the host in the middle (`Host(network=...)`): a redirect to another authority has to go through the same check, or it is a way round the policy.

* **A. Never follow (today).** The simplest, the safest, the same in both twins.
* **B. Follow, bounded** (for example 5 hops, same policy check on each hop, `Authorization` and cookies dropped on a change of host). It is more code and a list of rules that has to be the same in both twins **[not checked: that the rules above are the full list]**.

## 3. Proxies

* **A. Never read the variables (today).** A request goes to the authority it names; nothing leaks to a proxy that the guest did not choose.
* **B. A setting of the embedder** (`state->http_proxy`, or the transport `http_send`, which replaces the whole transport and already makes it possible). Note that `http_send` is already the way of an embedder that needs a proxy **[read: S0001]**.
* **C. Read the variables of the environment.** It makes the answer of the same guest depend on the environment of the machine, which a host of WASI should not do silently.

## 4. Proposal (a draft)

Redirects: A. Proxies: A, with `http_send` named in the docs as the way, and B only if an embedder asks. Reason: both change what a guest sees and what the network policy allows; neither is needed by a program today.

## 5. For the owner to decide

1. Is "never follow, never read the environment" the final position, or only the alpha's?
2. If a redirect is ever followed: the number of hops, the rule for headers, the policy check on each hop.
